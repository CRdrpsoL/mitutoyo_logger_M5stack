# Mitutoyo M5Unified Robust Logger

M5Stack Basic と Mitutoyo Digimatic ノギスを接続し、測定値をSDカードへ記録するスケッチです。

元スケッチで発生した「100件を超えた後に削除すると多数の記録が消える」「SD書込み失敗時にNo.が飛ぶ」「長押しで複数件記録される」といった問題を防ぐために、記録・削除・復旧処理を見直しています。

## ファイル構成

```text
mitutoyo_M5Unified_robust/
├─ mitutoyo_M5Unified_robust.ino
└─ README.md
```

Arduino IDEでは、`mitutoyo_M5Unified_robust.ino` を開いてコンパイル・書込みを行います。

## 動作環境

- M5Stack Basic（ESP32）
- M5Unified
- SDカード
- Mitutoyo Digimatic出力対応ノギスと接続回路

使用ピンは以下のとおりです。

| 用途 | GPIO |
| --- | ---: |
| Mitutoyo REQ | 26 |
| Mitutoyo DATA | 17 |
| Mitutoyo CLK | 16 |
| 記録スイッチ入力（ADC） | 36 |
| SDカードCS | 4 |

## 操作方法

- 外部の記録スイッチを1回押すと、測定値を1件記録します。
- スイッチは一度解放し、150ms以上経過するまで次の記録を受け付けません。長押しや一般的なチャタリングで複数件記録されない設計です。
- M5StackのBtnAを1秒以上長押しすると、現在の電源投入セッションで記録した最後の1件を削除します。成功時は`DEL`と表示し、低いBeep音が鳴ります。
- 記録成功時は`OK`と表示し、高いBeep音が鳴ります。記録失敗時は`X`と表示し、No.は進みません。

画面の`count`は、**次に記録するNo.**です。

## CSV仕様

記録先はSDカードの次のファイルです。

```text
/nashi.csv
```

各行はヘッダーなしの次の形式です。

```text
No.,測定値
```

例:

```text
1,25.42
2,25.55
1,30.10
2,30.08
```

電源投入またはリセットのたびに、新しい測定セッションとしてNo.1、件数0、平均値0から開始します。既存の`nashi.csv`は削除せず、その末尾へ追記します。CSV内でNo.が再び1になった位置が、新しい測定対象の開始位置です。

上の例では、No.1～2の測定が2セッション分記録されています。

## データ保護と復旧

- SDへの追記後、書込みバイト数、ファイルサイズ、末尾レコードを再オープンして検証します。
- 検証が成功した場合だけ、No.・件数・平均値を更新します。
- 追記前のファイルサイズと記録内容を小さなジャーナルファイルへ保存します。電源断後は、完全に書けた1行は採用し、部分書込みは追記前の状態へ戻します。
- 電源投入・リセット後は新しい測定対象としてNo.と平均値を初期化しますが、それまでのCSVデータは保持します。
- 削除やロールバックでは一時ファイルとバックアップファイルを利用し、置換途中の電源断から可能な限り復旧します。
- CSVの最後に不完全な行が残った場合は、起動時に末尾だけを修復します。
- 最終行削除はCSV全体を固定長配列へ格納しません。レコード数が100件、1000件以上でも、一定量のRAMで処理します。
- 新しいセッションでまだ1件も記録していない場合、削除操作で前の測定対象のデータを消すことはありません。

動作中にSDカード上へ以下の一時・復旧ファイルが現れることがあります。正常終了時は通常残りません。

```text
/nashi.tmp
/nashi.bak
/nashi.jrn
/nashi.jrt
```

## Mitutoyo通信と単位

Mitutoyo Digimaticの13ニブル形式を検証し、CLKの待機にはタイムアウトを設けています。通信断・不正フレーム時は測定値を記録しません。

現在はmm専用です。ノギスがinchモードの場合は`MM ONLY`を表示し、CSVへ記録しません。

## 調整可能な設定

スケッチ先頭の定数を変更すると、実機に合わせて調整できます。

| 定数 | 現在値 | 用途 |
| --- | ---: | --- |
| `RECORD_PRESS_THRESHOLD` | 100 | 記録スイッチを押したと判定するADC値（以下） |
| `RECORD_RELEASE_THRESHOLD` | 300 | 記録スイッチを解放したと判定するADC値（以上） |
| `RECORD_REARM_MS` | 150ms | 再記録を許可するまでの解放時間 |
| `DELETE_HOLD_MS` | 1000ms | BtnAの削除操作に必要な長押し時間 |
| `CSV_DECIMAL_PLACES` | 2 | CSVに保存する小数桁数 |
| `BATTERY_UPDATE_INTERVAL_MS` | 5000ms | バッテリー残量を取得する間隔 |

バッテリー残量の一時的な読取り失敗では、直前に取得できた正常値を表示し続けます。起動直後に一度も正常値を取得できない場合だけ`--%`と表示します。

## 注意事項

- 初めて修正版を使う前に、SDカードの`nashi.csv`をPCへバックアップしてください。
- 電源断やリセットは新しい測定セッションの開始として扱われます。意図しないリセットでも、次の記録はNo.1から始まります。
- 測定データである`nashi.csv`、および`nashi.tmp`・`nashi.bak`・`nashi.jrn`などのSDカード上のファイルは、GitHubへ追加しないでください。
- 実際のスイッチ回路によってADC値は異なります。反応しない、または意図せず記録される場合は、押下時・解放時の値を実測して閾値を調整してください。
- SDカードの物理的な故障、取り外し、電源断による全ての損失を完全に防げるわけではありません。重要な測定データは定期的にPCへ退避してください。
